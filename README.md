# InviteFlow

منصة SaaS للدعوات الرقمية — عربي/إنجليزي (RTL/LTR) مبنية بـ Next.js 15 وSupabase.

> **حالة المنتج:** مساران متاحان للعملاء الآن — **الدعوة الرقمية** (دعوة مصمَّمة لمناسبة) و**الدعوة بالرابط** (تسجيل مباشر: اسم، جوال، عدد المرافقين، وأسئلتك الخاصة، بدون تصميم دعوة). نظام التذاكر أُزيل من المنتج بالكامل. التفاصيل في [حالة المسارات](#حالة-المسارات).

## التقنيات المستخدمة

- **Next.js 15** (App Router) + **TypeScript**
- **Tailwind CSS v4** + **shadcn/ui** (مبني على Base UI)
- **Supabase**: PostgreSQL + Auth + Storage + Realtime
- **next-intl**: عربي/إنجليزي مع دعم RTL/LTR كامل
- **React Hook Form** + **Zod** للتحقق من صحة النماذج
- **Recharts** للرسوم البيانية في لوحة التحكم
- **qrcode** لتوليد رمز QR اختياري لرابط الدعوة العامة
- **bcryptjs** لتجزئة كلمات مرور حماية صفحات الدعوة
- **Vitest** + **pglite** (Postgres حقيقي عبر WASM) للاختبارات

## التشغيل المحلي

```bash
npm install
npm run dev
```

يفتح المشروع على `http://localhost:3000` ويُعيد التوجيه تلقائيًا إلى `/ar`. **المشروع يعمل ويُبنى بنجاح حتى بدون ربط Supabase** — الصفحات العامة تعمل بشكل طبيعي، وأي عملية تحتاج قاعدة بيانات فعلية (تسجيل دخول، إرسال RSVP...) تُظهر رسالة عربية/إنجليزية واضحة بدل الانهيار، لحين ربط مشروع Supabase حقيقي (انظر القسم التالي).

أوامر أخرى مفيدة:

```bash
npm run build        # بناء إنتاجي
npm run start         # تشغيل البناء الإنتاجي
npm run lint           # فحص ESLint
npm run format          # تنسيق الكود بـ Prettier
npm run test              # تشغيل كل الاختبارات
```

## إعداد Supabase

1. أنشئ مشروعًا جديدًا على [supabase.com](https://supabase.com).
2. من **Project Settings → API** انسخ:
   - `Project URL` → `NEXT_PUBLIC_SUPABASE_URL`
   - `anon public key` → `NEXT_PUBLIC_SUPABASE_ANON_KEY`
   - `service_role key` → `SUPABASE_SERVICE_ROLE_KEY` (⚠️ سرّي تمامًا، لا يُستخدم إلا على الخادم)
3. انسخ `.env.example` إلى `.env.local` واملأ القيم:
   ```bash
   cp .env.example .env.local
   ```
4. طبّق ملفات الـ migrations الموجودة في `supabase/migrations/` بالترتيب (أرقامها تضمن الترتيب الصحيح). أسهل طريقتين:
   - **عبر لوحة Supabase**: افتح **SQL Editor** والصق محتوى كل ملف بالترتيب ونفّذه.
   - **عبر Supabase CLI** (إن كان مثبّتًا لديك):
     ```bash
     supabase link --project-ref <project-ref>
     supabase db push
     ```
5. (اختياري، للتجربة) نفّذ `supabase/seed.sql` بنفس الطريقة **فقط على مشروع محلي عبر `supabase start`** — هذا الملف يُدخل صفوفًا مباشرة في `auth.users` وهو أمر غير مدعوم على مشروع Supabase مُستضاف (Hosted). على مشروع حقيقي، أنشئ حسابك عبر صفحة `/register` بدلًا من ذلك.
6. أعد تشغيل `npm run dev` بعد ملء `.env.local`.

> جميع الجداول محمية بسياسات **Row Level Security**، والعمليات الحسّاسة (مثل إرسال RSVP) تمر حصرًا عبر دوال قاعدة بيانات آمنة (`SECURITY DEFINER`) بدل الوصول المباشر للجداول — التفاصيل الكاملة في تعليقات ملفات الـ migrations.

## الحساب التجريبي

بعد تنفيذ `supabase/seed.sql` على مشروع Supabase محلي:

- **البريد الإلكتروني**: `demo@inviteflow.app`
- **كلمة المرور**: `password123`

يملك هذا الحساب منظمة تجريبية بثلاث مناسبات (زفاف منشور بردود RSVP، مؤتمر منشور، وحفل تخرج كمسودة).

على مشروع Supabase حقيقي (Hosted): سجّل عبر `/register` — تُنشأ لك منظمة شخصية تلقائيًا عند التسجيل.

## الاختبارات

```bash
npm run test
```

**84 اختبارًا** تغطي:

- **طبقة قاعدة البيانات** (`tests/db/`): تُشغَّل كل ملفات الـ migrations فعليًا على محرك Postgres حقيقي (`pglite`، بدون الحاجة لـ Docker)، وتتحقق من: تفعيل RLS وسياساته على كل جدول، الـ triggers التلقائية (إنشاء ملف شخصي، عضوية منظمة، إعدادات مناسبة افتراضية)، تقديم RSVP والإشعار التلقائي، رفض الرد بعد الموعد النهائي، وحماية Rate Limiting. تبقى بعض الاختبارات تغطي جداول ودوال التذاكر (`ticket_types`/`ticket_orders`) رغم إزالة واجهتها من التطبيق — الجداول والدوال نفسها ما زالت موجودة في قاعدة البيانات (حذفها يحتاج SQL مباشر، انظر [حالة المسارات](#حالة-المسارات)).
- **صحة ملفات الترجمة** (`tests/i18n-messages.test.ts`): يتأكد أن `ar.json` و`en.json` يحتويان بالضبط نفس المفاتيح، لمنع نسيان أي ترجمة.
- **دوال مساعدة نقية** (`tests/utils/`): توليد الـ slug، تصدير CSV، تحليل قائمة الضيوف الملصوقة (فواصل مختلفة، أرقام عربية، أسطر بدون رقم)، تطبيع أرقام الجوال السعودية، واستيراد الضيوف (لصق/VCF/CSV).

## النشر

الاستضافة الحالية **Railway** (`inviteflow-production.up.railway.app`). المشروع مستضاف سابقًا على Vercel وما زال يعمل هناك، لكن Railway هو المرجع.

في الحالتين المطلوب هو نفسه — أربعة متغيرات بيئة، ثم ربط الرابط بـSupabase:

- `NEXT_PUBLIC_SUPABASE_URL`
- `NEXT_PUBLIC_SUPABASE_ANON_KEY`
- `SUPABASE_SERVICE_ROLE_KEY`
- `NEXT_PUBLIC_APP_URL` (رابط النشر النهائي)

**Railway:**

```bash
railway init --name inviteflow
railway domain --port 3000                       # يولّد رابطًا عامًا
echo "<value>" | railway variable set <KEY> --stdin --skip-deploys
railway up
```

**Vercel:** استورد المستودع من [vercel.com/new](https://vercel.com/new) وأضف نفس المتغيرات في Environment Variables.

في الحالتين: من **Supabase → Authentication → URL Configuration** أضف رابط النشر إلى **Redirect URLs** (مطلوب لروابط تأكيد البريد واستعادة كلمة المرور).

> Supabase خدمة مستقلة تمامًا عن الاستضافة — نقل التطبيق بين Railway/Vercel لا يمسّ قاعدة البيانات أو المصادقة أو التخزين إطلاقًا.

## هيكل المشروع

```

lib/actions/              Server Actions (منطق حسّاس، جانب الخادم فقط)
lib/services/             منطق الأعمال والوصول لقاعدة البيانات (مفصول عن الواجهات)
lib/email/                طبقة تجريد البريد (Console + Resend)
lib/whatsapp/             طبقة تجريد واتساب (Console + Meta Cloud API)

lib/utils/rate-limit.ts   حماية Rate Limiting على النقاط العامة
lib/validations/          مخططات Zod
messages/{ar,en}.json      كل نصوص الواجهة (لا نصوص مباشرة داخل المكوّنات)
supabase/migrations/       16 ملف SQL مرقّمة بالترتيب
supabase/seed.sql          بيانات تجريبية
tests/                     اختبارات Vitest (قاعدة بيانات + وحدات + ترجمة)
```

## حالة المسارات

| المسار                 | حالة العميل                                                            |
| ---------------------- | ---------------------------------------------------------------------- |
| **الدعوة الرقمية**     | ✅ متاح — دعوة مصمَّمة لمناسبة، مع RSVP وأسئلة اختيارية                |
| **الدعوة بالرابط**     | ✅ متاح — تسجيل مباشر (اسم، جوال، عدد مرافقين، أسئلتك) بدون تصميم دعوة |
| **التذاكر والفعاليات** | ❌ أُزيل من المنتج بالكامل                                             |

نظام التذاكر (فئات، Mock/Moyasar Payment، QR، مسح ضوئي، صفحة check-in) حُذف من الكود بالكامل — لا صفحات، لا Server Actions، لا مكوّنات. الجداول والدوال المرتبطة به (`ticket_types`, `ticket_orders`, `tickets`, `ticket_check_ins`, `create_pending_ticket_order`...) ما زالت موجودة في قاعدة البيانات لأن حذف الجداول يحتاج تنفيذ SQL مباشرًا عبر لوحة Supabase (خارج قدرة الأدوات المستخدمة في بناء هذا المشروع) — لا شيء في التطبيق يكتب إليها أو يقرأ منها بعد الآن.

مسار الدعوة بالرابط لديه صفحة إنشاء منفصلة (`dashboard/events/new/rsvp`) ويشارك نفس بنية بيانات المناسبة مع الدعوة الرقمية حاليًا (بدون قالب عرض عام منفصل بعد) — فصله بصفحة عرض مبسّطة خاصة به على قائمة التطوير القادم.

## الميزات المكتملة (المرحلة الأولى)

- تسجيل/دخول/خروج/استعادة كلمة مرور، وحماية كاملة للوحة التحكم.
- **دخول بدون كلمة مرور**: رمز OTP عبر واتساب (رقم الجوال) أو عبر البريد الإلكتروني — «ابدأ مجانًا» و«تسجيل الدخول» صارا نفس التدفّق (الحساب يُنشأ تلقائيًا عند أول دخول). تفعيل مسار واتساب يتطلب ضبط Twilio كمزوّد SMS في لوحة Supabase؛ بدونه يظهر خطأ مترجَم يوجّه المستخدم لتبويب البريد.
- **رفع صورة أو فيديو غلاف** فعلي إلى Supabase Storage (صور حتى 5MB، فيديو حتى 50MB) مع معاينة وحذف، بدل لصق رابط.
- **اختيار الموقع على خريطة تفاعلية** (Leaflet + OpenStreetMap، بدون مفتاح API) مع دبوس قابل للسحب وبحث عناوين عبر Nominatim — والمخرج رابط خرائط جوجل عادي.
- **إضافة الضيوف بلصق قائمة كاملة**: سطر لكل ضيف بأي فاصل، مع تطبيع الأرقام العربية تلقائيًا، إضافة لاستيراد جهات الاتصال على أندرويد.
- إنشاء وإدارة مناسبات متعددة (مسودة/منشورة/منتهية) مع كل الحقول المطلوبة.
- صفحة دعوة رقمية عامة متجاوبة (RTL/LTR): صورة غلاف، مشاركة واتساب، إضافة للتقويم (ملف .ics حقيقي)، نسخ رابط، QR اختياري، وحماية بكلمة مرور اختيارية.
- RSVP بدون تسجيل دخول (سأحضر/لن أحضر/ربما)، مرافقون، رسالة، أسئلة مخصصة (6 أنواع)، وتعديل الرد عبر رابط آمن قبل الموعد النهائي.
- **الدعوة بالرابط**: مسار إنشاء منفصل للتسجيل المباشر (اسم، جوال، عدد مرافقين، أسئلة مخصصة) بدون تصميم دعوة — للمناسبات التي تحتاج أرقامًا دقيقة بسرعة.
- **استيراد ضيوف جماعي**: لصق قائمة، رفع ملف VCF، اختيار من جهات الاتصال (أندرويد)، أو رفع CSV — مع معاينة ومراجعة قبل الحفظ، وكشف تلقائي للأرقام المكررة أو غير الصحيحة.
- لوحة الضيوف: بحث، فلترة، تصدير CSV.
- لوحة إحصائيات: إجمالي المناسبات/المدعوين/الردود، رسم بياني لتوزيع الردود، وأحدث الردود.
- إشعارات داخلية لحظية (رد RSVP جديد) عبر Supabase Realtime.
- صفحات 404/خطأ/تحميل مخصصة ومترجمة لكل الأقسام.
- حماية Rate Limiting على نقاط RSVP العامة (مبنية بالكامل داخل Postgres، بدون حاجة لخدمة خارجية).
- تكامل بريد إلكتروني حقيقي (Resend) وواتساب (Meta Cloud API) — اختياريان عبر متغيرات بيئة، ويعملان تلقائيًا بوضع "محاكاة/تسجيل فقط" بدون ربطهما. انظر [الخدمات الخارجية الاختيارية](#الخدمات-الخارجية-الاختيارية).
- مراقبة أخطاء (Sentry) اختيارية عبر متغير بيئة واحد.
- خط أنابيب CI (GitHub Actions) يشغّل type-check/lint/test/build على كل push وPR.

## الخدمات الخارجية الاختيارية

ثلاث خدمات مبنية بالكامل ومربوطة بالتطبيق، وكل وحدة منها تعمل بوضع آمن افتراضي (محاكاة أو تسجيل بالـ console) بدون أي إعداد. لتفعيل الخدمة الحقيقية، أضف المتغيرات التالية في `.env.local` (محليًا) أو Railway/Vercel (بالإنتاج) — لا حاجة لتعديل أي كود:

| الخدمة                                                                       | المتغيرات                                           | بدون ربط                 | مع الربط                                |
| ---------------------------------------------------------------------------- | --------------------------------------------------- | ------------------------ | --------------------------------------- |
| **البريد الإلكتروني** ([Resend](https://resend.com)، مجاني)                  | `RESEND_API_KEY`                                    | يُسجَّل بالـ console فقط | يرسل فعليًا (تأكيد RSVP، إشعار المنظّم) |
| **واتساب** ([Meta Cloud API](https://developers.facebook.com/docs/whatsapp)) | `WHATSAPP_ACCESS_TOKEN`, `WHATSAPP_PHONE_NUMBER_ID` | يُسجَّل بالـ console فقط | رسائل واتساب فعلية (تأكيد RSVP)         |
| **مراقبة الأخطاء** ([Sentry](https://sentry.io)، مجاني)                      | `NEXT_PUBLIC_SENTRY_DSN`                            | معطّل تمامًا             | يرصد كل الأخطاء تلقائيًا                |

راجع `.env.example` للتفاصيل الكاملة (كل قسم فيه شرح من أين تحصل على القيمة).

⚠️ **ملاحظة عن واتساب**: خارج نافذة الـ 24 ساعة من محادثة العميل، تتطلب Meta استخدام "قالب رسالة" (Message Template) معتمد مسبقًا بدل نص حر — راجع Meta Business Manager عند التفعيل الفعلي.

بونص بدون أي ربط: زر "شارك ردك عبر واتساب" في صفحة شكر RSVP يفتح واتساب الضيف نفسه برسالة تأكيد جاهزة (رابط `wa.me` عادي، بدون API).

## الميزات المؤجلة (المرحلة الثانية)

- تذكيرات مجدولة (قبل/بعد المناسبة بيوم، قابلة للإلغاء)، رسائل جماعية للمؤكِّدين فقط، قائمة انتظار، إرسال صور بعد المناسبة.
- قوالب تصميم متقدمة ومحرر تصميم مرئي (جدول `event_designs` بحقل `design_json` مرن جاهز لذلك).
- **دعوة مؤسسية**: مسار ثالث منفصل لجهات تحتاج اسم شركة وشعارًا (يظهر كصورة عرض) ورفع تصميم دعوة خاص — يحتاج قرارًا معماريًا حول قيود واتساب Business API (رقم واتساب واحد لكل حساب مرتبط، لا يتغيّر لكل مؤسسة تلقائيًا) قبل البناء.
- باقات حسب عدد المدعوين، وقبول/اعتذار قابل للتخصيص حسب نوع المناسبة.
- تطبيق جوال.
- تصدير Excel حقيقي (`.xlsx`) — انظر الملاحظة الأمنية أدناه.
- خيار "اختيارات متعددة" (multi-choice) في الأسئلة المخصصة يُعرض حاليًا كحقل نصي بسيط بدل مربعات اختيار فعلية.
- قوالب دعوات جاهزة يختار منها المنظّم (رفع تصميم خاص متاح حاليًا).

## قرارات وملاحظات هامة

- **Next.js 15 بدل 16**: النسخة محددة صراحة كما طُلب. أحدث نسخة 15.x تحمل تبعيات داخلية (`postcss`/`sharp`) بثغرات معروفة لا يوجد لها إصلاح إلا بالترقية لـ Next 16 — تُركت كما هي عمدًا.
- **لا تصدير Excel حقيقي**: مكتبة `xlsx` (SheetJS) تحمل ثغرتين عاليتي الخطورة (Prototype Pollution وReDoS) بدون نسخة مُصححة على npm. استُبدلت بتصدير CSV (يفتح بنفس الجودة في Excel، ويدعم العربية عبر BOM).
- **الأمان**: لا يُستخدم Supabase Service Role إطلاقًا في المتصفح. كل عملية حسّاسة (مثل إرسال RSVP) تمر عبر دالة قاعدة بيانات `SECURITY DEFINER` تتحقق من كل قاعدة عمل قبل تنفيذها، وليس عبر سياسات RLS فضفاضة.
- **العمل بدون Supabase**: كل صفحة ومكوّن يتصل بـ Supabase (خادم أو متصفح) محميّ بفحص `isSupabaseConfigured()` بحيث لا ينهار المشروع أثناء التطوير قبل ربط مشروع حقيقي.
